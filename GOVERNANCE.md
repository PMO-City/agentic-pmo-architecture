# Governance

## Stewardship

PMO City stewards this public reference architecture. Stewardship means maintaining the public edition, reviewing challenges, protecting version history, and deciding when a new public release is ready.

The repository does not claim to be an independent standards body. It presents PMO City's reference architecture for the Agentic PMO and keeps its public claims proportionate to the evidence and governance available.

## Roles

- **Steward:** PMO City, accountable for public release decisions.
- **Architecture reviewer:** reviews changes to definitions, principles, boundaries, and conformance language.
- **Editorial reviewer:** reviews clarity, audience fit, examples, accessibility, and unsupported claims.
- **Contributor:** proposes corrections, questions, examples, or improvements through issues and pull requests.

Repository access should follow least privilege. Public readers do not need repository membership. Contributors should receive the smallest repository role that lets them do their work.

## What requires architecture review

Architecture review is required for changes to:

- the Agentic PMO definition;
- the nine-step operating loop;
- canonical concepts or their boundaries;
- human and AI authority responsibilities;
- evidence, state, learning, or conformance language;
- versioning and source-boundary claims; or
- a worked example that could change a reader's interpretation of the model.

Editorial corrections, link fixes, accessibility improvements, and typo corrections can follow normal pull-request review but should still be checked for semantic drift.

## Change control

Every accepted public change should be traceable to a pull request, issue, or recorded release decision. Released versions are tagged and are not silently rewritten. A later version may clarify an earlier one, but it should not erase its history.

## Challenges and disagreements

An issue may challenge a definition, request evidence, identify an inconsistency, or propose a clearer example. A disagreement does not become an architecture change merely because it is merged as a discussion or editorial correction.

## Security and privacy

Never commit credentials, tokens, private architecture files, private URLs, personal data, customer data, or internal deliberations. Report suspected secrets or security problems privately to the repository stewards rather than opening a public issue.
